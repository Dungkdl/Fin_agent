1. [CRITICAL] CLASSIFICATION EVALUATION ĐANG DÙNG TRADING THRESHOLD
============================================================

File liên quan:
src/finsight/experts/quant/training/pipeline.py

Hiện trạng:
Model dự đoán xác suất 3 lớp:

    y_prob = model.predict_proba(...)

Ban đầu pipeline có thể lấy:

    y_pred = np.argmax(y_prob, axis=1)

Đây là cách classification multiclass đúng.

Nhưng sau đó lại thay y_pred bằng logic kiểu:

    if P(BULLISH) >= threshold:
        BULLISH
    elif P(BEARISH) >= threshold:
        BEARISH
    else:
        SIDEWAYS

với threshold khoảng 0.50.

Ví dụ:

    BEARISH   = 0.42
    SIDEWAYS  = 0.31
    BULLISH   = 0.27

Argmax đúng:
    BEARISH

Nhưng code threshold hiện tại:
    BULLISH < 0.5
    BEARISH < 0.5

=> SIDEWAYS

Ví dụ khác:

    BEARISH   = 0.31
    SIDEWAYS  = 0.34
    BULLISH   = 0.35

Argmax:
    BULLISH

Nhưng threshold:
    BULLISH < 0.5
    BEARISH < 0.5

=> SIDEWAYS

Vì sao đây là lỗi rất lớn:
Bài toán của bạn là 3-class classification.

Trong bài toán 3 lớp, xác suất tự nhiên có thể xoay quanh:

    0.33 / 0.33 / 0.33

Không có lý do một class phải vượt 0.50 mới được xem là prediction.

Threshold 0.50 phù hợp hơn với:
- quyết định trading confidence,
- hoặc binary classification,

chứ không phải cách tính class prediction cho multiclass evaluation.

Hậu quả:
Rất nhiều prediction có class cao nhất đúng nhưng không vượt 0.50
sẽ bị ép thành SIDEWAYS.

Điều này làm:
- Macro F1 giảm mạnh
- Balanced Accuracy giảm
- Recall BULLISH/BEARISH giảm
- Confusion matrix bị méo

Cách sửa:
Classification evaluation phải dùng:

    y_pred = np.argmax(y_prob, axis=1)

Sau đó tính:

    Accuracy
    Balanced Accuracy
    Macro F1
    Weighted F1
    Precision
    Recall
    Confusion Matrix
    Log Loss
    Brier Score

Trading threshold phải tách thành một nhánh riêng.

Kiến trúc đúng:

                    model probabilities
                           |
              -------------------------
              |                       |
       classification              trading
        evaluation                 strategy
              |                       |
          ARGMAX                 threshold
              |                       |
        F1 / Accuracy           Buy / Sell / No trade

2. [CRITICAL] CATBOOST 33.33% CÓ DẤU HIỆU BỊ COLLAPSE VỀ SIDEWAYS
============================================================

Kết quả:
CatBoost Balanced Accuracy khoảng 33.33%
Macro F1 khoảng 0.13

Đây là dấu hiệu đáng nghi.

Nếu model bị post-processing thành gần như:

    SIDEWAYS
    SIDEWAYS
    SIDEWAYS
    SIDEWAYS
    ...

thì Balanced Accuracy của bài toán 3 class sẽ gần:

    (Recall_BEAR + Recall_SIDEWAYS + Recall_BULL) / 3

Nếu:
    Recall_BEAR ≈ 0
    Recall_SIDEWAYS ≈ 1
    Recall_BULL ≈ 0

thì:

    Balanced Accuracy ≈ 1/3 = 33.33%

Con số này khớp rất sát với CatBoost hiện tại.

Điều này không chứng minh chắc chắn model tốt,
nhưng chứng minh rằng metric hiện tại rất có thể đang bị logic threshold làm hỏng.

Việc cần làm:
Sau khi sửa argmax, bắt buộc in:
- confusion matrix
- support mỗi class
- precision mỗi class
- recall mỗi class
- số prediction mỗi class

Nếu prediction distribution trở nên cân bằng hơn,
thì lỗi post-processing chính là nguyên nhân lớn.

3. [CRITICAL] THRESHOLD TUNING ĐANG DÙNG IN-SAMPLE PREDICTION
============================================================

Hiện trạng:
Pipeline train final model trên toàn bộ train + validation,
sau đó lại predict chính dataset đó để chọn threshold.

Logic gần giống:

    model.train(df_train_val)

    y_prob_train = model.predict_proba(df_train_val)

    search best threshold

Vấn đề:
Model đã nhìn thấy chính các sample được dùng để tune threshold.

Đây là in-sample optimization.

Threshold có thể bị overfit.

Cách đúng:
Threshold phải tune từ OOF predictions.

Ví dụ:

Fold 1:
    train -> validation prediction

Fold 2:
    train -> validation prediction

Fold 3:
    train -> validation prediction

Ghép toàn bộ validation predictions lại:

    OOF probabilities

Sau đó:
    tune threshold trên OOF

Cuối cùng:
    freeze threshold

Rồi mới:
    train final model
    evaluate untouched holdout

Không dùng final holdout để chọn threshold.

    P(SIDEWAYS) = 0.32

Nếu chỉ test từ 0.50,
nhiều signal tốt sẽ không bao giờ được xem xét.

Khuyến nghị:

    0.34
    0.36
    0.38
    0.40
    0.42
    0.45
    0.50
    0.55
    0.60

Nhưng threshold trading KHÔNG nên chọn chỉ bằng F1.

Nên xem:
- trade count
- precision BULLISH
- average future return
- return
- Sharpe
- max drawdown
- turnover
- transaction cost

Ví dụ:
Threshold cao hơn có thể ít trade nhưng chất lượng tốt hơn.

5. [HIGH] LOG HIỆN GỌI BALANCED ACCURACY LÀ ACCURACY
============================================================

Hiện log đang có dạng:

    Accuracy (Holdout): ...

nhưng metric bên trong lại là:

    balanced_accuracy_score(...)

Hai metric này khác nhau.

Accuracy:
    số prediction đúng / tổng sample

Balanced Accuracy:
    trung bình recall của các class

Trong class imbalance,
hai con số có thể khác đáng kể.

Cách sửa:
Log riêng:

    Accuracy
    Balanced Accuracy
    Macro F1
    Weighted F1
    Log Loss
    Brier Score

Không gọi Balanced Accuracy là Accuracy.

6. [HIGH] CẦN THÊM CONFUSION MATRIX VÀ DISTRIBUTION CỦA PREDICTION
============================================================

Hiện tại chỉ nhìn Macro F1 và Balanced Accuracy chưa đủ.

Cần in:

True label distribution:
    BEARISH
    SIDEWAYS
    BULLISH

Prediction distribution:
    BEARISH
    SIDEWAYS
    BULLISH

Confusion matrix:

                    Pred Bear   Pred Side   Pred Bull

True Bear
True Side
True Bull

Vì sao cần:
Nếu model prediction gần như toàn SIDEWAYS,
metric thấp là do class collapse.

Nếu prediction phân bố hợp lý nhưng vẫn sai nhiều,
lúc đó mới nói feature/label yếu.

8. [MEDIUM] LABEL 5 NGÀY HIỆN CÓ THỂ QUÁ NHIỄU
============================================================

Hiện target gần giống:

    future_return_5d
        /
    rolling daily volatility

Sau đó threshold:

    normalized_return > +0.5 -> BULLISH
    normalized_return < -0.5 -> BEARISH
    else -> SIDEWAYS

Vấn đề:
Numerator là 5-day return,
nhưng denominator là volatility 1-day.

Ví dụ:
daily volatility = 4%

Threshold:
    0.5 * 4% = 2%

Tức:
    +2% trong 5 ngày -> BULLISH
    -2% trong 5 ngày -> BEARISH

Với crypto,
±2% trong 5 ngày có thể chỉ là noise.

Điều này có thể làm label khó học.

Khuyến nghị A/B test:

Label A:
    future_5d_return / vol_1d

Label B:
    future_5d_return / (vol_1d * sqrt(5))

Label C:
    future_5d_return / historical_5d_volatility

Ví dụ:
vol_1d = 4%

vol_5d xấp xỉ:
    4% * sqrt(5) ≈ 8.94%

Threshold 0.5:
    khoảng ±4.47%

Target như vậy có thể bớt noise hơn.

Không nên đổi ngay rồi mặc định tốt hơn.
Phải A/B test bằng OOF + holdout.

    df = df[df["close_time"] >= min_time]

Tốt hơn nữa:
dataset manifest nên ghi rõ:

    min_timestamp
    max_timestamp
    number_of_symbols
    number_of_samples
